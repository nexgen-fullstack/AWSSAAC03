> 🎬 **Історія Хмаринки.** Перший розпродаж у хмарі пройшов ідеально — сайт витримав. А наступного ранку дві тривоги. Боти з тисяч IP-адрес засипали сторінку входу спробами підібрати паролі покупців, а хтось підставляв у пошук товарів дивні рядки на кшталт `' OR 1=1 --`. І ще: хтось із розробників випадково залив у публічний репозиторій ключ доступу — і вночі в акаунті з'явилися 40 потужних серверів, що майнили криптовалюту. Цей розділ — про те, як AWS захищає від атак **ззовні** і як **помічає** зловмисника, що вже всередині.

> 🖼️ **Образ.** Хмаринка — торговий центр. **WAF** — охоронець на вході, що перевіряє кожного відвідувача за списком прикмет («у масці — не пускати», «з того району — не пускати», «хто заходить уже сотий раз за хвилину — зупинити»). **Shield** — дамба від повені: коли натовп у мільйон людей намагається штурмувати двері, щоб ніхто інший не пройшов. **GuardDuty** — камери відеоспостереження з розумним аналітиком, що помічає підозрілу поведінку. **Inspector** — інженер, що обходить будівлю й шукає несправні замки. **Macie** — перевіряльник, що знаходить забуті на видноті документи з персональними даними. **Security Hub** — пульт охорони, куди стікаються всі сигнали.

## Від чого захищаємось: карта атак

| Атака | Що відбувається | Рівень | Захист в AWS |
|---|---|---|---|
| **DDoS** (об'ємна) | Мільйони пакетів «забивають» канал чи сервер | L3/L4 | **Shield Standard** (автоматично), Shield Advanced, CloudFront, Global Accelerator |
| **HTTP flood** | Шквал «нормальних» HTTP-запитів на важкі сторінки | L7 | **WAF** (rate-based rules), Shield Advanced |
| **SQL injection, XSS** | Шкідливий код у полях форм і URL | L7 | **WAF** (managed rules) |
| **Боти, підбір паролів** | Автоматизовані спроби входу, скрапінг цін | L7 | **WAF** Bot Control, захист від захоплення акаунтів, CAPTCHA |
| **Скомпрометовані ключі** | Хтось діє в акаунті від твого імені | API | **GuardDuty**, CloudTrail, найменші привілеї |
| **Вразливості ПЗ** | Стара бібліотека з відомою дірою (CVE) | ОС/код | **Inspector** + патчі (Patch Manager) |
| **Витік даних** | Персональні дані лежать там, де не повинні | Дані | **Macie**, шифрування, Block Public Access |

## AWS WAF: веб-файрвол рівня 7 {#waf}

**AWS WAF** (Web Application Firewall) перевіряє **HTTP/HTTPS-запити** за правилами і вирішує: пропустити, заблокувати, порахувати або показати CAPTCHA / перевірку «ти не робот».

**Де працює WAF:** Amazon **CloudFront**, **Application Load Balancer**, **API Gateway** (REST API), **AWS AppSync**, **Cognito User Pool**, **App Runner**, Amplify. **Не** на Network Load Balancer і **не** прямо на EC2 — це улюблена пастка іспиту.

Правила збирають у **Web ACL**:

- **AWS Managed Rules** — готові набори від AWS: базовий захист від поширених атак (OWASP Top 10), SQL injection, відомі шкідливі вхідні дані, IP з поганою репутацією, анонімні проксі й VPN, правила для Linux/Windows/PHP. Є й набори від партнерів з AWS Marketplace.
- **Власні правила:** за IP-адресами (IP sets), **країною** (geo match), заголовками, розміром тіла, регулярними виразами.
- **Rate-based rules** — обмеження частоти: «не більше 500 запитів за 5 хвилин з однієї IP-адреси на /login». Головна зброя проти HTTP flood і підбору паролів.
- **Bot Control**, **Account Takeover Prevention**, **Account Creation Fraud Prevention** — платні керовані набори проти ботів і шахрайства з акаунтами.

:::example 🧩 Web ACL для Хмаринки (на CloudFront)
1. AWS Managed Rules — Core rule set і SQL database → блокують `' OR 1=1 --`.
2. IP reputation list → блокуємо відомі ботнети.
3. Rate-based rule на `/login`: понад 100 запитів за 5 хвилин з однієї IP → CAPTCHA.
4. Geo match: панель адміністратора `/admin/*` — лише з України (решта — блок).
5. Спершу всі нові правила — у режимі **Count**, щоб подивитися, чи не заблокують вони справжніх покупців, і лише потім **Block**.
:::

## AWS Shield: захист від DDoS {#shield}

- **Shield Standard** — **безкоштовно й автоматично** для всіх клієнтів AWS. Захищає від найпоширеніших атак рівнів 3–4 (SYN flood, UDP reflection) на інфраструктуру AWS, зокрема CloudFront і Route 53.
- **Shield Advanced** — платна підписка (близько **$3 000 на місяць на організацію**, з річним зобов'язанням). Дає:
  - **Shield Response Team (SRT)** — експерти AWS 24/7, які допомагають під час атаки;
  - **захист від рахунку**: компенсація витрат на масштабування, спричинене DDoS (кредити);
  - розширене виявлення і **автоматичне пом'якшення атак рівня 7** разом з WAF (WAF для захищених ресурсів без додаткової плати);
  - захист ресурсів: **CloudFront, Route 53, Global Accelerator, Elastic Load Balancing, EC2 з Elastic IP**;
  - детальні звіти й метрики атак.

Архітектурний захист від DDoS: ставити перед застосунком **CloudFront** і/або **Global Accelerator** (величезна пропускна здатність edge-мережі поглинає атаку), використовувати **Auto Scaling**, тримати сервери в **приватних підмережах** за балансувальником.

## Firewall Manager, Network Firewall, DNS Firewall {#firewalls}

- **AWS Firewall Manager** — **централізоване** керування правилами безпеки в **усіх акаунтах AWS Organizations**: web ACL WAF, Shield Advanced, **Security Groups**, Network Firewall, DNS Firewall, сторонні файрволи. Нові акаунти й ресурси отримують політики **автоматично**. Потребує Organizations і AWS Config.
- **AWS Network Firewall** — керований **stateful**-файрвол і система запобігання вторгненням (IPS) **на рівні VPC**: фільтрує весь трафік, а не лише HTTP; правила сумісні з **Suricata**; фільтрація вихідного трафіку за **доменними іменами** («сервери можуть ходити лише на `*.amazonaws.com` і сайт платіжного партнера»). Часто розгортається в окремій «inspection VPC» за Transit Gateway.
- **Route 53 Resolver DNS Firewall** — блокує DNS-запити з VPC до **шкідливих доменів** (готові списки AWS: малварь, ботнети) — зупиняє «дзвінок додому» зараженого сервера.

:::mnemo 🧠 Хто на якому рівні
**WAF** — L7, лише веб (HTTP). **Shield** — DDoS (L3/L4, з Advanced — і L7). **Network Firewall** — увесь трафік VPC, IPS, домени. **DNS Firewall** — DNS-запити. **Security Groups / NACL** — базові порти й адреси ([розділ 14](#ch/vpc-security)). **Firewall Manager** — пульт, що розставляє все це по всіх акаунтах.
:::

## Виявлення загроз: GuardDuty {#guardduty}

**Amazon GuardDuty** — «розумні камери» акаунта. Вмикається одним кліком, **без агентів** і без налаштування журналів: GuardDuty сам аналізує **CloudTrail** (API-виклики), **VPC Flow Logs** (мережевий трафік) і **DNS-журнали**, застосовуючи машинне навчання, виявлення аномалій і розвідку загроз AWS.

Що він знаходить:

- **скомпрометовані облікові дані**: виклики API з незвичних країн, із відомих шкідливих IP, запуск незвичних сервісів о третій ночі;
- **криптомайнінг** на серверах;
- сервер, що спілкується з **командним центром ботнету** (C&C) або сканує порти;
- спроби вимкнути журнали, змінити налаштування безпеки.

Додаткові плани захисту розширюють огляд: **S3 Protection** (підозрілий доступ до даних), **EKS** і **Runtime Monitoring** (контейнери й сервери зсередини), **Malware Protection** (сканування дисків EC2 і нових об'єктів у S3), **RDS Protection** (підозрілі входи в бази), **Lambda Protection**. Нові можливості поєднують окремі сигнали в **послідовності атаки** (extended threat detection).

**Автоматична реакція:** знахідка GuardDuty → правило **EventBridge** → функція **Lambda** або **SSM Automation**: ізолювати сервер (замінити Security Group на «карантинну»), зробити знімок диска для розслідування, відкликати ключі, надіслати сповіщення.

## Вразливості, чутливі дані, розслідування {#inspector-macie}

- **Amazon Inspector** — **постійне сканування вразливостей**: серверів **EC2** (пакети ОС, відомі CVE; з агентом SSM або без агента), **образів контейнерів у ECR**, функцій **Lambda** (залежності й код), плюс аналіз **мережевої досяжності** («цей порт відкритий в інтернет»). Кожна знахідка отримує оцінку ризику з урахуванням середовища. Inspector **знаходить** — латає **SSM Patch Manager**.
- **Amazon Macie** — знаходить **чутливі дані в S3** за допомогою машинного навчання і шаблонів: персональні дані (імена, адреси, номери паспортів, телефони), номери банківських карток, облікові дані. А ще показує bucket, які **публічні**, **незашифровані** чи **відкриті іншим акаунтам**.
- **Amazon Detective** — **розслідування**: будує граф зв'язків з CloudTrail, VPC Flow Logs і знахідок GuardDuty, щоб знайти **першопричину** інциденту і все, до чого торкався зловмисник.

:::mnemo 🧠 Три сервіси, які постійно плутають
**GuardDuty** = **загрози** («хтось поводиться підозріло»). **Inspector** = **вразливості** («у тебе незачинене вікно»). **Macie** = **чутливі дані в S3** («паспорти клієнтів лежать на видноті»). А **Detective** = «що сталося і хто винен».
:::

## Security Hub: пульт охорони {#securityhub}

**AWS Security Hub** збирає знахідки з **GuardDuty, Inspector, Macie, IAM Access Analyzer, Firewall Manager, AWS Config** і партнерських рішень **в одному місці** й автоматично перевіряє акаунти на відповідність **стандартам безпеки**: AWS Foundational Security Best Practices, **CIS** AWS Foundations Benchmark, **PCI DSS**, NIST. Результат — оцінка безпеки і список конкретних проблем («bucket без блокування публічного доступу», «root без MFA»). Для кількох акаунтів і регіонів — агрегація в одному адміністративному акаунті.

:::note 🆕 Зміни 2025 року
У червні 2025 року AWS перейменував класичний Security Hub на **Security Hub CSPM** (перевірка налаштувань за стандартами), а назву **Security Hub** отримав новий, ширший сервіс, що корелює сигнали всіх сервісів безпеки й допомагає пріоритезувати ризики. Для іспиту суть та сама: «одна панель стану безпеки всіх акаунтів + перевірки стандартів» → Security Hub.
:::

## Відповідність і аудит {#compliance}

- **AWS Artifact** — портал **звітів відповідності AWS** (SOC 1/2/3, ISO 27001, PCI DSS) і **угод** (наприклад, BAA для медичних даних за HIPAA). Аудитор просить «доказ, що дата-центри AWS сертифіковані» → Artifact.
- **AWS Audit Manager** — **автоматично збирає докази** для твоїх аудитів (GDPR, HIPAA, PCI, SOC 2): знімки налаштувань, журнали, результати перевірок — у готовий звіт.
- **AWS Config** — історія конфігурацій ресурсів і правила відповідності з автовиправленням ([розділ 41](#ch/monitoring)).
- **CloudTrail** — хто і коли викликав API.

:::mnemo 🧠 CloudTrail, Config, CloudWatch
**CloudTrail** — «хто і коли» (журнал дій). **Config** — «яким був і чи правильний» (стан ресурсів). **CloudWatch** — «як працює» (метрики, логи, аларми). Питання «хто видалив bucket?» → CloudTrail; «чи всі диски зашифровані і що змінилось учора?» → Config; «CPU сервера понад 90%» → CloudWatch.
:::

:::lab 🧪 Спробуй у справжньому AWS: увімкни «камери» акаунта
**Вартість:** GuardDuty і Inspector мають **30-денний безкоштовний пробний період**; після нього для навчального акаунта — вимкни. **Час:** 20 хвилин.
1. **GuardDuty** → **Get started** → **Enable GuardDuty**. Нічого більше налаштовувати не треба.
2. **Settings** → **Generate sample findings** — GuardDuty створить приклади знахідок усіх типів (позначені `[SAMPLE]`). Відкрий кілька: `CryptoCurrency:EC2/BitcoinTool`, `UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration` — прочитай опис, рівень критичності й рекомендації.
3. **EventBridge** → **Rules** → **Create rule** → Event pattern: AWS services → **GuardDuty** → **GuardDuty Finding** → ціль: тема **SNS** зі своїм email (створи тему прямо тут або в SNS і підтверди підписку). Згенеруй зразки знахідок ще раз — лист має прийти.
4. **Inspector** → **Activate Inspector** — подивись дашборд покриття (поки що ресурсів для сканування немає; повернешся сюди після розділу про EC2).
5. **Security Hub** (або Security Hub CSPM) → увімкни стандарт **AWS Foundational Security Best Practices** — через кілька годин побачиш оцінку свого навчального акаунта.
**Прибери за собою:** після завершення курсу (або пробного періоду) — GuardDuty → Settings → **Suspend/Disable**; Inspector → **Deactivate**; Security Hub → **Disable**; видали правило EventBridge і тему SNS.
:::

#### 💡 Запам'ятай

- **WAF** — L7: SQL injection, XSS, боти, **rate-based rules**, geo match. Працює на **CloudFront, ALB, API Gateway, AppSync, Cognito** — **не на NLB/EC2**.
- **Shield Standard** — безкоштовно, L3/L4. **Shield Advanced** — ~$3 000/міс: **SRT 24/7**, **компенсація витрат**, L7 з WAF.
- **Firewall Manager** — централізовані правила WAF/Shield/SG/Network Firewall в усіх акаунтах організації.
- **Network Firewall** — stateful-файрвол/IPS для VPC, фільтрація за доменами. **DNS Firewall** — блок шкідливих доменів.
- **GuardDuty** — загрози (ML по CloudTrail, VPC Flow Logs, DNS), без агентів. **Inspector** — вразливості (EC2, ECR, Lambda). **Macie** — чутливі дані в S3. **Detective** — розслідування.
- **Security Hub** — єдина панель + стандарти (CIS, PCI, AWS FSBP). **Artifact** — звіти AWS. **Audit Manager** — докази для твого аудиту.
- Реакція на інциденти: **знахідка → EventBridge → Lambda / SSM Automation**.

#### 🎯 Як питають на іспиті

- Захистити вебзастосунок на ALB від SQL injection і XSS → **AWS WAF з managed rules на ALB**
- Обмежити кількість запитів з однієї IP-адреси (HTTP flood, підбір паролів) → **WAF rate-based rule**
- Заблокувати доступ до сайту з певних країн → **WAF geo match** (або CloudFront geo restriction)
- DDoS-захист з експертами 24/7 і компенсацією витрат на масштабування → **AWS Shield Advanced**
- Керувати правилами WAF і Security Groups у всіх акаунтах, включно з новими → **AWS Firewall Manager**
- Фільтрувати вихідний трафік VPC за доменними іменами, IPS → **AWS Network Firewall**
- Незвичні API-виклики, криптомайнінг, скомпрометовані ключі → **Amazon GuardDuty**
- Сканувати сервери EC2 і образи ECR на відомі CVE → **Amazon Inspector**
- Знайти персональні дані й номери карток у bucket S3 → **Amazon Macie**
- Знайти першопричину інциденту безпеки → **Amazon Detective**
- Одна панель стану безпеки всіх акаунтів і перевірки CIS/PCI → **AWS Security Hub**
- Аудитор просить звіт SOC 2 чи PCI про інфраструктуру AWS → **AWS Artifact**
- Автоматично ізолювати сервер при знахідці GuardDuty → **EventBridge rule → Lambda (карантинна Security Group)**
- Вебзастосунок за Network Load Balancer, потрібен захист L7 → **поставити CloudFront або ALB з WAF (WAF не підтримує NLB)**

#### ⚠️ Пастки

- WAF **не** ставиться на NLB і прямо на EC2.
- Shield Standard уже ввімкнений у всіх — «увімкнути Shield Standard» не є окремою дією.
- GuardDuty не блокує атаки сам — він **виявляє**; блокування — через автоматизацію чи інші сервіси.
- Inspector **знаходить** вразливості, але не латає — латає Patch Manager.
- Macie працює з **S3** (не з базами даних і не з дисками EC2).

- Amazon GuardDuty
= SQL injection — атака рівня 7 у вмісті HTTP-запиту. Її розпізнає WAF (AWS Managed Rules). Shield — від DDoS, NACL бачить лише IP і порти, GuardDuty виявляє загрози в акаунті, а не фільтрує веб-запити.

? Сторінку входу атакує бот, надсилаючи тисячі запитів на хвилину з кожної з кількох сотень IP-адрес. Як обмежити це з найменшими зусиллями?
- Додати кожну IP-адресу в Security Group з Deny
+ Налаштувати WAF rate-based rule для шляху /login
- Збільшити кількість серверів в Auto Scaling
- Увімкнути Shield Standard
= Rate-based rule автоматично блокує (або вимагає CAPTCHA) IP-адреси, що перевищують ліміт запитів за період. У Security Group взагалі немає Deny, а масштабування лише збільшить рахунок.

? Інтернет-магазин хоче захист від великих DDoS-атак з допомогою експертів AWS під час атаки і компенсацією додаткових витрат на масштабування. Що обрати?
- AWS Shield Standard
+ AWS Shield Advanced
- AWS WAF
- Amazon Inspector
= Shield Advanced дає доступ до Shield Response Team 24/7 і захист від зростання рахунку через DDoS, а також розширене виявлення. Shield Standard — лише базовий безкоштовний захист L3/L4.

? Служба безпеки хоче виявляти незвичну активність в акаунтах: виклики API з підозрілих IP, криптомайнінг на серверах, використання вкрадених ключів — без встановлення агентів. Що обрати?
+ Amazon GuardDuty
- Amazon Inspector
- Amazon Macie
- AWS Config
= GuardDuty аналізує CloudTrail, VPC Flow Logs і DNS-журнали та виявляє загрози за допомогою ML і розвідки загроз, без агентів. Inspector шукає вразливості, Macie — чутливі дані в S3, Config — відповідність налаштувань.

? Компанія повинна знайти всі об'єкти S3 з номерами банківських карток і паспортними даними клієнтів. Який сервіс це робить?
- Amazon GuardDuty
- AWS Security Hub
+ Amazon Macie
- Amazon Detective
= Macie використовує машинне навчання і шаблони, щоб знаходити чутливі дані (PII, фінансові дані) в S3 і показувати ризикові налаштування bucket.

? У компанії 60 акаунтів в AWS Organizations. Потрібно, щоб усі ALB і CloudFront у всіх акаунтах, включно з новими, мали однаковий набір правил WAF. Що використати?
- Налаштувати WAF вручну в кожному акаунті
+ AWS Firewall Manager з політикою WAF для організації
- AWS Shield Advanced в management account
- SCP, що вимагає WAF
= Firewall Manager централізовано застосовує політики WAF, Shield Advanced, Security Groups і Network Firewall до всіх акаунтів організації і автоматично — до нових ресурсів. SCP може заборонити дії, але не налаштує правила WAF.

? Потрібно автоматично ізолювати сервер EC2, щойно GuardDuty виявить на ньому криптомайнінг. Як це побудувати? (Оберіть 2)
+ Правило Amazon EventBridge, що реагує на знахідки GuardDuty потрібного типу
+ Функція Lambda, що замінює Security Group сервера на карантинну без правил
- Налаштувати GuardDuty блокувати сервер самостійно
- Правило AWS WAF на сервері EC2
- Amazon Macie для сканування сервера
= GuardDuty лише виявляє. Знахідки надходять в EventBridge, правило запускає Lambda (або SSM Automation), яка ізолює сервер. WAF не ставиться на EC2, Macie працює з S3.
