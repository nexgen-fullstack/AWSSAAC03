> 🎬 **Історія Хмаринки.** Олена відкриває карту: покупці в Україні, незабаром — у Польщі й Німеччині. «Де фізично житиме наш магазин? — питає вона. — І що буде, якщо в тому місці вимкнуть світло?» Юрист нагадує: персональні дані клієнтів з ЄС мають оброблятися за правилами GDPR. Перше справжнє рішення архітектора — **де** розмістити систему. Для цього треба знати, як AWS фізично влаштований по всьому світу.

> 🖼️ **Образ.** AWS — мережа **міст** по всьому світу. Кожне місто — **регіон** (Region). У кожному місті кілька окремих **районів** — **зон доступності** (Availability Zones): зі своїми електростанціями, водогонами й дорогами, щоб пожежа чи блекаут в одному районі не зачепили інші. Між районами — швидкісні тунелі. А біля людей по всьому світу стоять сотні **кіосків** — **edge locations**, де швидко видають популярний товар (контент), не везучи його щоразу з міського складу.

## Регіони {#regions}

**Регіон AWS** — географічна область (місто чи агломерація), де AWS має кілька ізольованих дата-центрів. Регіонів понад три десятки, на всіх континентах, крім Антарктиди. Кожен має код, який ти бачитимеш скрізь:

| Код | Місто | Коментар |
|---|---|---|
| `eu-central-1` | Франкфурт | Найближчий великий регіон до України, повний набір сервісів |
| `eu-west-1` | Ірландія | Один з найстаріших і найбільших регіонів Європи |
| `eu-north-1` | Стокгольм | Часто дешевший, «зелена» енергія |
| `eu-west-2` / `eu-west-3` | Лондон / Париж | |
| `eu-central-2` | Цюрих | Вимоги Швейцарії щодо даних |
| `eu-south-1` / `eu-south-2` | Мілан / Іспанія | |
| `us-east-1` | Північна Вірджинія | Найбільший і найстаріший регіон; тут з'являються нові сервіси; деякі глобальні налаштування живуть саме тут |

Ключові властивості регіонів:

- **Ізоляція.** Регіони незалежні один від одного. Аварія в одному не зачіпає інші.
- **Дані не переїжджають самі.** AWS не копіює твої дані в інший регіон, поки ти сам не налаштуєш реплікацію чи копіювання. Це основа для вимог **data residency** («дані мають лишатися в ЄС»).
- **Більшість сервісів — регіональні.** Сервер, база, черга створюються в конкретному регіоні й живуть там.

### Як обрати регіон: чотири питання

1. **Закони і вимоги (compliance).** Де дозволено зберігати дані? Для клієнтів з ЄС — регіон у ЄС. Це питання **завжди перше**: інші переваги не важливі, якщо регіон заборонений.
2. **Близькість до користувачів (latency).** Менша відстань — швидший сайт.
3. **Доступність сервісів.** Не кожен сервіс і не кожен тип сервера є в кожному регіоні. Нові сервіси часто з'являються спершу в `us-east-1`.
4. **Ціна.** Ціни в регіонах різні (часто на 5–20%).

:::example 🧭 Рішення для Хмаринки
- Закон: клієнти з ЄС → регіон у ЄС. ✅ Франкфурт, Ірландія, Стокгольм — усі підходять.
- Затримка: Львів, Варшава, Берлін → Франкфурт найближчий (десятки мілісекунд).
- Сервіси: у Франкфурті є все потрібне.
- Ціна: трохи дорожче за Стокгольм, але затримка важливіша для магазину.

**Висновок:** основний регіон — `eu-central-1` (Франкфурт). Резервний на випадок аварії цілого регіону — `eu-west-1` (Ірландія): інше місто, інша енергосистема, теж ЄС. Важкі нічні задачі без вимог до затримки колись можна буде перенести в дешевший регіон.
:::

## Зони доступності {#az}

**Availability Zone (AZ)** — один або кілька дата-центрів у межах регіону з **незалежним** живленням, охолодженням і мережею. У кожному регіоні щонайменше **три** зони (у великих — більше). Зони:

- **фізично рознесені** — на відстані, достатній, щоб пожежа, повінь чи блекаут не зачепили дві зони одночасно (але в межах приблизно 100 км одна від одної);
- **з'єднані** швидкими приватними оптоволоконними каналами із затримкою в **одиниці мілісекунд** — достатньо для **синхронної** реплікації баз даних між ними.

Назви зон — код регіону плюс літера: `eu-central-1a`, `eu-central-1b`, `eu-central-1c`.

**Головне правило архітектора:** усе важливе розгортай **щонайменше у двох зонах доступності**. Якщо зона `a` зникне через аварію, копії в зоні `b` продовжать обслуговувати клієнтів. Це і є **висока доступність** (high availability, HA) в AWS. Сервіси, у назві яких є «Multi-AZ», роблять це за тебе.

:::deep 🔬 Глибше: чому «eu-central-1a» у тебе і в мене — різні зони
Щоб клієнти рівномірно розподілялися по зонах (а не всі вибирали «a»), AWS для кожного акаунта **випадково зіставляє** літери з фізичними зонами. Твоя `eu-central-1a` може бути моєю `eu-central-1c`. Якщо двом акаунтам треба домовитися про ту саму фізичну зону (наприклад, при спільному використанні підмереж), використовують **AZ ID** — стабільний ідентифікатор на кшталт `euc1-az1`, однаковий для всіх акаунтів. На іспиті це іноді з'являється як «забезпечити, що ресурси двох акаунтів в одній фізичній зоні → використовуй AZ ID».
:::

## Edge-локації: кіоски біля людей {#edge}

Окрім регіонів, AWS має **сотні точок присутності** (понад 600) у великих містах світу — **edge locations**. Там не запускають звичайні сервери чи бази даних. Там працюють сервіси, яким важливо бути **ближче до користувача**:

- **Amazon CloudFront** — мережа доставки контенту (CDN): кешує фото, відео, сторінки біля людей ([розділ 18](#ch/edge)).
- **Amazon Route 53** — DNS, що відповідає з найближчої точки ([розділ 17](#ch/route53)).
- **AWS Global Accelerator** — вхід у швидку приватну мережу AWS найближче до користувача.
- **AWS WAF і AWS Shield** — захист від атак ще до того, як трафік дійде до регіону.

Покупниця у Варшаві отримає фото товарів не з Франкфурта, а з найближчої edge-локації — за кілька мілісекунд.

## Особливі «філії» AWS

Коли потрібна ще менша затримка або дані мусять лишатися в конкретному місці:

| Варіант | Де фізично | Для чого | Образ |
|---|---|---|---|
| **AWS Local Zones** | У великому місті, як розширення найближчого регіону | Одноцифрові мілісекунди для мешканців міста: ігри, стрімінг, рендеринг, відеомонтаж | Філія AWS у твоєму місті |
| **AWS Wavelength** | Усередині 5G-мережі мобільного оператора | Ультранизька затримка для мобільних пристроїв: AR/VR, ігри, IoT, автономні машини | AWS у вежі 5G біля телефона |
| **AWS Outposts** | У **твоєму** дата-центрі — стійки або сервери AWS | Дані мають фізично лишатися в тебе, або потрібна мінімальна затримка до локальних систем; ті самі API AWS | Шафа-філія AWS у твоїй серверній |

## Мережа AWS між регіонами

Регіони й edge-локації з'єднує **глобальна приватна мережа AWS** — власні оптоволоконні канали, зокрема підводні кабелі. Трафік між регіонами й сервісами AWS іде нею, а не загальним інтернетом: стабільніше, швидше, безпечніше (трафік між дата-центрами AWS шифрується). Сервіси на кшталт Global Accelerator і CloudFront дозволяють і твоїм користувачам якомога швидше «зайти» в цю мережу.

## Регіональні й глобальні сервіси

Більшість сервісів — **регіональні**. Але кілька — **глобальні**: налаштовуються один раз для всього акаунта.

| Глобальні | Регіональні (приклади) |
|---|---|
| IAM (користувачі, ролі, політики) | EC2, EBS, VPC |
| Route 53 (DNS) | RDS, Aurora, DynamoDB |
| CloudFront (CDN) | Lambda, SQS, SNS |
| AWS Organizations | S3 bucket (ім'я — глобально унікальне, але сам bucket живе в одному регіоні) |
| Global Accelerator | KMS-ключі, секрети, сертифікати ACM* |

\* Сертифікат для CloudFront треба створювати саме в `us-east-1` — одна з улюблених пасток ([розділ 11](#ch/encryption)).

## Від чого захищатися: рівні відмов

Архітектор завжди питає: **відмову чого має пережити система?**

| Що може зламатися | Як захиститися в AWS | Ціна |
|---|---|---|
| Один сервер | Кілька серверів + балансувальник + автозаміна (Auto Scaling) | Низька |
| Ціла зона доступності | Розгортання в **2+ зонах** (Multi-AZ) | Помірна — стандарт для prod |
| Цілий регіон | Копія системи або даних в **іншому регіоні** (multi-region, DR) | Висока — лише коли бізнес цього вимагає |
| Помилка людини, атака | Бекапи, версії, заборона видалення, розмежування доступів | Помірна — потрібна завжди |

Відомий вислів CTO Amazon Вернера Фогельса: *«Everything fails, all the time»* — «Усе ламається, постійно». Добра архітектура не намагається зробити так, щоб нічого не ламалося, — вона робить так, щоб поломки **не помічали клієнти**.

:::note 📌 Квоти сервісів (Service Quotas)
У кожному регіоні в акаунта є **ліміти**: скільки серверів певного типу можна запустити, скільки VPC створити тощо. Більшість лімітів («м'які») можна підняти запитом. Важливий нюанс для аварійного відновлення: якщо резервний регіон доведеться раптово навантажити, квоти там треба підняти **заздалегідь** — під час аварії чекати схвалення запиту ніколи.
:::

1. Відкрий у браузері сторінку **AWS Global Infrastructure** (пошук: «AWS global infrastructure map») — знайди європейські регіони, кількість зон у кожному, Local Zones і edge-локації.

#### 💡 Запам'ятай

- **Регіон** — географічна область з кількома ізольованими зонами; дані між регіонами самі не переїжджають.
- **Зона доступності** — один чи кілька дата-центрів з незалежним живленням і мережею; у регіоні їх щонайменше три; між ними — швидкі канали.
- **Висока доступність = 2+ зони.** Захист від втрати регіону = інший регіон.
- Вибір регіону: **закон → затримка → сервіси → ціна**.
- **Edge-локації** — сотні точок для CloudFront, Route 53, Global Accelerator, WAF, Shield.
- **Local Zones** — місто, **Wavelength** — 5G, **Outposts** — твій дата-центр.
- Глобальні сервіси: **IAM, Route 53, CloudFront, Organizations**. Більшість решти — регіональні.

#### 🎯 Як питають на іспиті

- Дані клієнтів мають фізично лишатися в ЄС → **регіон у ЄС (і заборона інших регіонів політиками організації)**
- Застосунок має пережити збій одного дата-центру → **розгортання в кількох Availability Zones**
- Застосунок має пережити збій цілого регіону → **multi-region: копія даних і інфраструктури в іншому регіоні**
- Одноцифрові мілісекунди затримки для користувачів конкретного мегаполіса → **AWS Local Zones**
- Ультранизька затримка для мобільних пристроїв у 5G-мережі → **AWS Wavelength**
- Дані мають лишатися у власному дата-центрі, але потрібні сервіси й API AWS → **AWS Outposts**
- Два акаунти мають розмістити ресурси в одній фізичній зоні → **орієнтуватися на AZ ID, а не на назву зони**
- Під час аварії резервний регіон не зміг запустити потрібну кількість серверів → **заздалегідь підняти Service Quotas у DR-регіоні**

#### ⚠️ Пастки

- Edge-локація — **не** регіон і не зона: там не запускають EC2 чи RDS.
- Multi-AZ захищає від втрати зони, але **не** від втрати регіону.
- Ім'я bucket S3 глобально унікальне, але сам bucket — **регіональний**.
- Назва зони (`eu-central-1a`) у різних акаунтах може вказувати на різні фізичні зони.

## ✅ Перевір себе

:::quiz
? Компанія з Польщі зобов'язана за законом зберігати персональні дані клієнтів лише в ЄС. Який критерій вибору регіону AWS має бути першим?
+ Відповідність законам і вимогам щодо розміщення даних
- Найнижча ціна
- Найбільша кількість доступних сервісів
- Найменша затримка до офісу компанії
= Вимоги регуляторів (compliance, data residency) — жорсткі обмеження: якщо регіон не відповідає закону, його не можна обрати незалежно від ціни чи швидкості. Серед дозволених регіонів далі дивляться на затримку, сервіси й ціну.

? Що таке Availability Zone?
- Окрема країна, де AWS має дата-центри
+ Один або кілька дата-центрів у регіоні з незалежним живленням, охолодженням і мережею
- Точка кешування контенту біля користувачів
- Стійка AWS у дата-центрі клієнта
= AZ — ізольована частина регіону з власною інфраструктурою. Регіон складається щонайменше з трьох AZ, з'єднаних швидкими каналами. Точка кешування — це edge location, стійка в дата-центрі клієнта — Outposts.

? Вебзастосунок має продовжувати роботу навіть при повній відмові одного дата-центру AWS. Яке рішення мінімально достатнє?
- Запустити більший сервер в одній зоні
+ Розгорнути сервери й базу даних щонайменше у двох Availability Zones одного регіону
- Розгорнути застосунок у двох регіонах в режимі active-active
- Зробити щоденний бекап у S3
= Збій дата-центру чи зони закриває розгортання в кількох AZ (Multi-AZ). Два регіони теж захистили б, але це значно дорожче й складніше, ніж вимагає задача. Бекап не дає безперервної роботи.

? Ігровій компанії потрібна одноцифрова мілісекундна затримка для гравців у конкретному великому місті, де немає регіону AWS. Що обрати?
- AWS Outposts
+ AWS Local Zones
- Amazon CloudFront
- Додатковий регіон
= Local Zones — розширення регіону у великих містах з мінімальною затримкою для мешканців. Outposts ставлять у власний дата-центр клієнта, CloudFront кешує контент, але не запускає ігрові сервери.

? Які з цих сервісів AWS є глобальними, а не регіональними? (Оберіть 2)
+ AWS IAM
- Amazon EC2
+ Amazon Route 53
- Amazon RDS
- Amazon SQS
= IAM і Route 53 налаштовуються для всього акаунта одразу. EC2, RDS і SQS створюються в конкретному регіоні.

? Два акаунти компанії мають розмістити ресурси в одній фізичній зоні доступності, щоб мінімізувати затримку між ними. На що орієнтуватися?
- На назву зони, наприклад eu-central-1a — вона однакова для всіх акаунтів
+ На AZ ID, наприклад euc1-az1 — він однаковий для всіх акаунтів
- На IP-адреси серверів
- На назву регіону
= AWS для кожного акаунта випадково зіставляє літери зон із фізичними зонами, тож «1a» в різних акаунтах може бути різними зонами. AZ ID — стабільний ідентифікатор фізичної зони.
